# 系统架构总览

## 设计哲学

Claude Code（深度创作） + DeepSeek V4 Pro（百万上下文审查） 双模型互补协作。

Claude Code 的优势不在于"写作能力更强"，而在于**能主动调用工具**——读写文件、执行脚本、启动 Sub-agent。因此 Claude Code 是整个系统的**调度中枢**，不只负责思考，还负责管理文件、维护进度、调用外部能力。

## 三层架构

### 调度层
- **Claude Code Orchestrator（主会话）**
  - 理解意图 → 调度 Sub-agent → 读写文件 → 汇报进度
  - 上下文持续维护：project_status.md + 最近操作记录

### 创作层
- **创作 Agent**（Sub-agent）：世界观构建、角色设计、大纲规划、正文写作
- **品质 Agent**（Sub-agent）：文笔编辑、节奏优化、情绪流检查、逻辑校验
- **市场 Agent**（Sub-agent）：对标分析、钩子评估、标题优化、平台适配
- **DeepSeek 审查引擎**：1M 上下文检查、伏笔追踪、角色状态机

### 数据流
- Orchestrator
  - 读: system/（架构定义）, skills/（操作方法）, templates/（样板）
  - 写: output/（小说产出）, meta/（进度/状态）
  - → Sub-agent（创作任务）：输入=项目配置+已有产出+Skill 定义，输出=写入 output/
  - → DeepSeek API（审查任务）：输入=全书/卷/章节正文，输出=一致性报告→ meta/consistency_reports/

## 关键设计决策

| 决策 | 选择 | 理由 |
|------|------|------|
| Agent 调用方式 | Sub-agent (Task tool) | 需要独立推理 + 多次迭代时使用 |
| Skill 定义方式 | 独立 .md 文件 | 可被 Claude 读取、易于维护 |
| 上下文传递 | 文件系统作为数据总线 | 避免 prompt 膨胀 |
| 角色状态追踪 | 文件 + DeepSeek 周期性审查 | 自动 vs 深度审查互补 |
| 目标平台 | 番茄小说（独家） | 系统流脑洞爽文赛道，高流量 + 广告分成变现 |
| 市场参考 | templates/tomato_system_market_essence.md | 写作前读取，确保贴合平台偏好 |

## 番茄模式写作标准

| 维度 | 标准 |
|------|------|
| 章节长度 | 2000-3000 字 |
| 段落 | 短段落 ≤ 3 句，尽量 1-2 句 |
| 对话占比 | 40-60%，推进情节 |
| 结尾 | 每章必留钩子 |
| 节奏 | 每 2000 字小高潮，每 3 章爽点，每 10 章大高潮 |
| 核心指标 | 完读率 > 8%（潜力股门槛） |
| 开局 | 黄金三章：困境→金手指→小高潮 |
| 文笔 | 简洁直白，不堆砌辞藻 |
| 风格 | 轻松搞笑 + 脑洞反套路 |

## 写作铁律（爽、好读、不堆砌）

- **写的是小说，不是散文**。禁止堆砌华丽词藻、景物描写、氛围渲染
- 短句短段，一句话说不清就拆两句
- 对话优先：能对话推进的，不用叙述
- 每段必须推进情节或展现角色，没有过渡段
- 读起来像刷短视频：不用动脑就能跟上
- 故事趣味性第一：不好笑/不爽/不推剧情就删

## 合理擦边指南（男频）

- 擦边是为了「会心一笑」，不是为了写色情
- 「暗示比明说有效」：点到为止，留白让读者脑补
- 推荐方式：暧昧对话、系统恶趣味、后宫向设定、身份反差、系统搞事
- 底线：不能有性行为描写、不涉未成年人、不涉强迫、不涉乱伦
- 暧昧到「牵手、拥抱、意外身体接触」为止
- 擦边戏码必须剧情需要它，不是为了擦边而擦边

## 流式脑洞爽文专项规则

- **系统类型**：反套路/缺陷系统/人格化系统优先（2026 趋势）
- **主角人设**：幽默、脑洞大、不正经用系统
- **情绪曲线**：「压抑→爆发→新挑战→更大爆发」循环
- **信息密度**：每次只给读者一个信息点，不堆砌设定
- **前 30 章**：节奏密度高于后续，决定读者去留
